# РАКОВАРНЯ 73 — Premium Food E-commerce

Премиальный прототип витрины раков для Ульяновска и области. Название, цены и отдельные сведения в каталоге являются проектными допущениями, пока владелец не подтвердит их для коммерческого запуска.

## Концепция
- **Бренд:** РАКОВАРНЯ «ЕХАЛ ГРЕКА»
- **Регион:** Ульяновск и Ульяновская область
- **Визуальный язык:** Dark Editorial / Quiet Luxury
- **Ассортимент в текущем интерфейсе:** живые раки четырёх категорий
- **Связь:** телефон и подготовка заказа для ручной отправки через Telegram

## Что реализовано
- Адаптивная одностраничная витрина.
- Hero-слайдер, каталог, калькулятор количества и корзина.
- Сохранение корзины в localStorage браузера.
- Форма с проверкой имени и телефона.
- Подготовка текста заказа и копирование в буфер обмена.
- Открытие Telegram-профиля по номеру телефона. Пользователь самостоятельно вставляет подготовленный текст и нажимает «Отправить».
- Мобильная навигация и интерфейсы корзины/оформления.

**Важно:** текущая форма на опубликованной GitHub Pages версии не отправляет заявку автоматически, не вызывает Telegram Bot API и не передаёт данные на сервер сайта. Успешное открытие Telegram или копирование текста не означает, что продавец получил заказ. Заказ считается отправленным только после того, как пользователь вручную отправит сообщение в Telegram.

## Приём заказов

Режим зависит от платформы публикации:

- **GitHub Pages:** статическая версия не имеет серверного API. Форма подготавливает текст заказа, предлагает скопировать его и отправить продавцу вручную. Интерфейс прямо сообщает, что заявка не отправлена автоматически.
- **Cloudflare Pages:** при сборке командой `npm run build:cloudflare` фронтенд обращается к `/api/order`, который обслуживает `functions/api/order.ts`. Обработчик проверяет входные данные, рассчитывает сумму по серверному каталогу и отправляет сообщение через Telegram Bot API.
- **Vercel:** `api/order.ts` — отдельный вариант серверного обработчика; текущая конфигурация GitHub Pages его не запускает.

Для автоматической отправки на Cloudflare необходимо создать Pages-проект, подключить репозиторий и задать секреты `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` в настройках проекта. Не добавляйте токены в клиентский код, Git или обычные переменные фронтенда.

**Важно:** наличие функции и успешная сборка не подтверждают, что Cloudflare-проект создан, секреты настроены или сообщения реально доходят продавцу. До проверки боевого окружения автоматический приём заказов считать неактивированным. Перед коммерческим запуском также необходимы защита от спама/злоупотреблений, проверка доставки сообщений и согласование обработки персональных данных.

## Документы
Шаблоны находятся в `public/privacy.html` и `public/terms.html`; GitHub Pages копирует их в `dist`. Они содержат незаполненные поля и не являются готовыми юридическими документами. Перед коммерческим запуском заполните сведения об операторе, фактических получателях данных, целях и сроках обработки, оплате, доставке и возвратах; согласуйте документы с реальными процессами и проверьте их с юристом.

## Где менять каталог
Витрина и клиентские цены находятся в `src/App.tsx`. Серверные каталоги продублированы в `api/order.ts` и `functions/api/order.ts`. При изменении цен синхронизируйте все три места. Серверные обработчики рассчитывают стоимость по ID товара, а не по сумме, присланной браузером.

## Подготовка Cloudflare Pages (альтернативная публикация)

Для Cloudflare Pages используйте:
- **Framework preset:** Vite (или None, если интерфейс предлагает ручную настройку)
- **Build command:** `npm run build:cloudflare`
- **Build output directory:** `dist`
- **Production branch:** `main`
- **Root directory:** `/`
- **Node.js:** 22

Команда `build:cloudflare` собирает сайт с корневым путём `/`, а `npm run build` сохраняет путь `/raki/` для GitHub Pages. CI теперь проверяет обе сборки отдельно; после Cloudflare-сборки выполняется GitHub Pages-сборка, чтобы каталог `dist` для текущего сайта остался с правильным base path.

Порядок подключения:
1. В аккаунте владельца Cloudflare откройте **Workers & Pages → Create application → Pages → Connect to Git**.
2. Подключите репозиторий `marcostavar24633-cyber/raki`, выберите production branch `main` и укажите настройки сборки выше.
3. В настройках Pages-проекта откройте **Settings → Variables and Secrets** и добавьте именно как **Secrets**:
   - `TELEGRAM_BOT_TOKEN` — токен Telegram-бота;
   - `TELEGRAM_CHAT_ID` — ID чата, куда бот должен отправлять заявки.
4. Сохраните секреты и запустите production deployment. Не присылайте значения секретов в чат и не добавляйте их в Git.
5. Сначала проверьте безопасные отрицательные сценарии: GET должен вернуть 405, запрос без секретов — 503, неверный Content-Type — 415, некорректный JSON — 400. Не отправляйте тестовый заказ с настоящими контактами в рабочий Telegram.
6. После подтверждения окружения выполните отдельную проверку доставки с согласованным тестовым чатом, не используя персональные данные реального клиента.

Файл `wrangler.toml` описывает имя проекта и каталог сборки, но не создаёт Pages-проект и не подключает аккаунт. Секреты нельзя задавать как переменные фронтенда. Пока проект не создан, секреты не добавлены и deployment не проверен, автоматический приём заказов не активирован.

**Ограничение перед коммерческим запуском:** серверная функция пока не имеет настроенного Cloudflare Rate Limiting. До публичного включения формы нужно добавить ограничение частоты запросов и завершить проверку юридических оснований обработки контактных данных.

## Публикация на GitHub Pages
Workflow `.github/workflows/pages.yml`:
1. Устанавливает Node.js 22 и зависимости.
2. Выполняет `npm run build`.
3. Публикует папку `dist` в GitHub Pages.

Источник публикации в **Settings → Pages** должен быть **GitHub Actions**.

Адрес: https://marcostavar24633-cyber.github.io/raki/

Vite настроен на путь `/raki/`, необходимый для публикации проекта в подпапке GitHub Pages.

## Поисковые системы и индексация
- Основной адрес сайта: `https://marcostavar24633-cyber.github.io/raki/`.
- Sitemap: `https://marcostavar24633-cyber.github.io/raki/sitemap.xml`.
- Файл robots.txt проекта публикуется по адресу `https://marcostavar24633-cyber.github.io/raki/robots.txt`.
- Google Search Console и Яндекс Вебмастер пока не подтверждены и не подключены к аккаунтам владельца. Наличие sitemap и метаданных само по себе не подтверждает индексацию.
- Для подключения добавьте URL-префикс сайта в Google Search Console и Яндекс Вебмастер, получите выданный сервисом уникальный HTML-файл или meta-тег подтверждения и добавьте его в репозиторий. Не используйте чужие или придуманные verification-токены.
- После подтверждения отправьте sitemap в каждом сервисе и проверьте статус индексирования главной страницы.
- GitHub Pages проекта размещён в подпапке `/raki/` на общем домене `github.io`. Проект не управляет корневым `/robots.txt` домена `github.io`; для полного контроля над корневой robots.txt и адресом сайта рекомендуется собственный домен.
