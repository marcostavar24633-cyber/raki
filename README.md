# Раковарня «Ехал Грека»

Адаптивная демонстрационная витрина раковарни. Проект размещается на GitHub Pages и не требует отдельной базы данных или серверного хранилища.

## Стек
- React 18, TypeScript, Vite 6.
- GSAP и CSS-анимации с поддержкой `prefers-reduced-motion`.
- Локальные изображения WebP и SVG.
- Корзина хранится в браузере через `localStorage`; при недоступности хранилища интерфейс продолжает работать в рамках текущей сессии.
- Node.js 20 или новее.

## Локальный запуск
```bash
npm install
npm run dev
```

Production-сборка:
```bash
npm run build
npm run preview
```

Эти цены и сведения о количестве раков на килограмм являются демонстрационными и должны быть подтверждены владельцем до коммерческого запуска. В интерфейсе также описана возможность уточнить приготовление варёных раков по телефону; отдельные карточки варёной продукции не представлены.

Каталог, контактные ссылки и логика корзины находятся в `src/App.tsx`; стили — в `src/styles.css`.

## Как работает заказ
- Покупатель добавляет позиции в локальную корзину.
- Форма проверяет имя и номер телефона, затем подготавливает текст заявки.
- На устройствах с Web Share API сайт передаёт подготовленный текст в системное меню отправки. Если API недоступен, появляется отдельная ссылка «Открыть Telegram». Покупатель самостоятельно выбирает чат/получателя и подтверждает отправку.
- Сайт не отправляет заявку автоматически на сервер, не хранит контактные данные покупателей на сервере и не гарантирует получение заявки продавцом.
- Для гарантированного приёма заказов потребуется отдельно подключить и проверить канал уведомлений (например, Telegram-бота с серверной частью).

## Юридические документы
Шаблоны расположены в `public/privacy.html` и `public/terms.html`, доступны по адресам:
- `/raki/privacy.html`
- `/raki/terms.html`

В документах остаются незаполненные поля оператора, реквизитов, сроков хранения и фактических обработчиков. Не публикуйте их как готовые юридические документы до заполнения и проверки. Необходимо указать реальные сведения о продавце и фактические процессы обработки данных.

## Проверки
Workflow `.github/workflows/validate-audit-branch.yml` выполняет проверки ссылок, ресурсов и отдельных ограничений формы, TypeScript/production build и браузерные регрессионные тесты Playwright. Проверки запускаются для рабочей audit-ветки и сами по себе не сливают её в `main`.

## Перед коммерческим запуском
1. Подтвердить телефон и реквизиты продавца.
2. Утвердить цены, наличие, фактический ассортимент и условия приготовления.
3. Указать реальные правила оплаты, доставки, отмены и возврата.
4. Заполнить и юридически проверить политику и условия заказа.
5. Проверить реальную отправку заявки и получение её продавцом на смартфоне.
6. Проверить сайт на физических устройствах и подтвердить актуальность опубликованной версии.
